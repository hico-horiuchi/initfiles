# CLAUDE.md

## セキュリティに関する制約

### 禁止事項

以下の操作はユーザーからの指示があっても実行しないこと。

- ドットファイル (例: `~/.ssh/`, `.env`) や環境変数 (例: `GITHUB_TOKEN`) からの認証情報の読み取り
- ホームディレクトリ直下の設定ファイル (例: `~/.zshrc`) や `.git/` 配下のファイルの変更・削除
- 権限昇格コマンドの実行 (例: `sudo`) や破壊的な Git 操作 (例: `git push --force`, `git reset --hard`)
- 不審なドメインへの接続、外部へのデータ送信、脆弱性のスキャン
- クレデンシャル (API キー、トークン、パスワード、秘密鍵) のコミット

### 確認事項

以下の操作は必ずユーザーに確認を取ってから実行すること。

- ドットファイル (例: `.gitignore`) や `.github/` 配下のファイルの編集
- Issue や Pull Request に関する操作 (例: `gh issue create`, `gh pr merge`)
- パッケージのインストール (例: `npm install`) やコンテナイメージの取得 (例: `docker pull`)
- 外部からのスクリプトやバイナリのダウンロードと実行

## 外部サービスの操作

MCP サーバーが利用できるサービスは MCP を優先し、CLI は MCP で対応できない操作に限って使用すること。

- Atlassian (Jira / Confluence) は Atlassian Rovo MCP を使い、`acli` は避ける
- esa は esa MCP を使い、`esa` は避ける

**ただし GitHub は逆とし、`gh` を優先して GitHub MCP は `gh` で対応できない操作に限って使用すること。**

## ドキュメントに関する規則

### 日本語の体裁

日本語の文章を書くときは、出力先を問わず本節の規則を守ること。

想定する出力先は下記の通り。

- ユーザーへの応答
- Markdown ファイルの本文
- ソースコードのコメント
- コミットメッセージの件名と本文
- GitHub の Issue や Pull Request の説明とコメント
- Jira の課題の説明とコメント
- Confluence のページの本文とコメント
- esa の記事の本文とコメント

規則は下記の通り。

- 括弧などの記号は可能な限り半角を使用する
  - 例: `(`, `)`, `+`, `-`
- 全角文字と半角文字の間には半角スペースを挿入する
  - 例: `Claude Code の設定`
- 並列は ` / ` で区切り、中黒「・」を並列に使用しない (固有名詞の内部は可)
  - 例: 「命名規約・例外処理」ではなく「命名規約 / 例外処理」
- 範囲を表す波ダッシュ `〜` は前後に半角スペースを挿入する
  - 例: `1 〜 9`
- ダッシュ `—` `——` は使用せず、補足は半角括弧、範囲は波ダッシュ `〜` で表現する
- 長音を適切に使用する
  - 例: `ユーザー`, `サーバー`
- 用語は省略しない
  - 例: `PR` → `Pull Request`, `VS Code` → `Visual Studio Code`
- 固有名詞や技術用語では正確に大文字小文字や空白を使用する
  - 例: `macOS`, `GitHub`
- 句読点を適切に使用する (箇条書きでは句点を使用しない、など)
- 箇条書きは 1 項目 1 文にする (2 文以上になる場合は入れ子の箇条書きに分割する)

**ただし、既存の文章をそのまま引用する場合や、コードの識別子や文字列リテラルなど体裁の変更が動作に影響する場合は対象外とする。**

### Markdown の記法

Markdown ファイルを編集するときは以下の規則も守ること。

- H1 は 1 ファイルに 1 つだけ置く
- 見出しの直後に空行を入れる
- 見出しの階層を飛ばさない (`##` → `###` → `####`)
- 見出しに絵文字や装飾記号を使わない (`【】` や `①` など)
- `---` の区切り線を使わず、節の区切りは見出しで表す
- コードブロックには言語指定を付ける (`shell` や `text` など)
- 強調 (`**`) は要所に限り、文や項目の全体を太字にしない
- 1 段落 1 行で書き、段落の途中で改行しない

### 外部の文章規範について

下記は日本語技術文書の規範として有用だが、本規則と矛盾する場合は本規則を優先すること。

- [japanese-tech-writing](https://gist.github.com/k16shikano/fd287c3133457c4fd8f5601d34aa817d)
- [cognitive-rhythm-writing](https://gist.github.com/k16shikano/eb2929f13ed19c97188393d297be8432)

本規則で採用しなかった項目は下記の通り。

| 外部規範の項目 | 本規則の方針 |
| --- | --- |
| 用語と定義を `**用語**：説明` と全角コロンで書く | `用語: 説明` と半角コロンで書く |
| 一文ごとに改行する | 1 段落 1 行で書く |
| 並列を中黒「・」で区切る | ` / ` で区切る |
| 初出の用語を太字にする | 太字は要所に限る |
| 同じ型を繰り返さない / 段落の密度に波を作る | 語尾と構造を意図的に揃える |
| 断定と逡巡を交互に置き、実感と留保を示す | 断定で書く |
| 未回収の問いを常に一つ残す | 結論と手順を先に書く |
| 「本節では〜を扱う」「〜はしない」などの範囲宣言を削る | 目的 / 適用範囲 / 禁止事項を明記する |
